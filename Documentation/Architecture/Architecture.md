# Архитектура

## Границы проекта

`_NorthernLands` владеет правилами игры. Starter Assets отвечает только за движение,
камеру и исходную анимацию персонажа. Игровые системы не должны напрямую зависеть от
его внутренних классов.

## Поток запуска

1. Сцена `00_Bootstrap` создаёт `GameBootstrap`.
2. Bootstrap регистрирует постоянные службы.
3. Службы инициализируются в порядке регистрации.
4. Машина состояний переводит игру в главное меню.
5. При закрытии службы завершаются в обратном порядке.

## Хранение состояния

| Данные | Файл | Удаляются при сбросе забега |
|---|---|---:|
| Уровень, мир, позиция, золото, квесты, таланты | `northern_lands_save.json` | Да |
| Резервная копия прохождения | `northern_lands_save.backup.json` | Да |
| Постоянная раса и будущий метапрогресс | `northern_lands_profile.json` | Нет |

Ссылки на объекты сцен в сохранения не записываются. Используются стабильные строковые
идентификаторы и простые сериализуемые значения.

## Зависимости

- UI вызывает публичные команды систем, но не меняет характеристики напрямую.
- `PlayerInputRouter` превращает устройства и экранные кнопки в игровые действия.
- Контроллер Starter Assets получает движение через адаптер.
- Бой, инвентарь, расы и квесты не знают, какой контроллер перемещения установлен.
- Переходы выполняются через `ISceneFlowService`.

## Боевой прототип 0.2

- `HealthComponent` — единая точка здоровья, брони, блока и смерти;
- `DamageCalculator` — единая формула прототипа;
- `PlayerCombatController` — комбо и тяжёлая атака без зависимости от модели;
- `SimpleThirdPersonMotor` и `SimpleThirdPersonCamera` — временная бесплатная замена,
  позволяющая проверить сцену до импорта Starter Assets;
- `PlayerInputRouter` — физический и виртуальный ввод;
- `TrainingEnemyController` — временный враг без NavMesh;
- UI передаёт команды через `PlayerInputRouter` и не меняет здоровье напрямую.
